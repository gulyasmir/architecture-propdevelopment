# Задание 1. Разработка проверочного листа по безопасности данных

## 1. **Проанализируйте диаграмму и описание системы PropDevelopment**

#### ** Классификация данных по стандартам ISO/IEC 27001 и 27002**

Данные компании PropDevelopment классифицируются по четырём категориям:


| **Категория данных**               | **Примеры данных**                                                                                                                                                                                                                             |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Публичные данные**               | Открытая информация на сайте компании, маркетинговые материалы, рекламные предложения, новости компании.                                                          |
| **Внутренние данные**             | Внутренние отчёты, данные аналитики BI, статистика продаж, информация о ходе строительных работ.                                                                             |
| **Конфиденциальные данные** | Данные клиентов и собственников (ФИО, контактные данные, история сделок), финансовые данные компании, договоры, API-контракты с партнёрами. |
| **Секретные данные**               | Доступы к базам данных, ключи API, пароли, персональные данные клиентов, данные для аутентификации и авторизации.                                                |

#### ** Оценка рисков для каждой категории данных**


| **Категория данных**               | **Риск**                                | **Причина актуальности**                                                                                                                              | **Оценка риска**  |
| ------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------- |
| **Публичные данные**               | **Искажение данных**         | Мошенники могут изменять информацию о недвижимости, вводя клиентов в заблуждение.                  | Значительный     |
|                                                   | **Обесценивание данных** | Устаревшие данные (например, информация о наличии квартир) могут снижать доверие клиентов.   | Незначительный |
| **Внутренние данные**             | **Утечка данных**               | Неконтролируемый доступ к аналитике BI может привести к утечке инсайдерской информации.        | Значительный     |
|                                                   | **Потеря данных**               | Некорректные настройки резервного копирования могут привести к потере критических данных. | Значительный     |
|                                                   | **Неактуальные данные**   | Некорректные данные в CRM могут приводить к ошибкам в маркетинговых кампаниях.                           | Незначительный |
| **Конфиденциальные данные** | **Утечка данных**               | Ошибки в API-политиках могут привести к доступу к данным клиентов посторонними.                          | Критический       |
|                                                   | **Искажение данных**         | Неконтролируемый доступ к CRM может позволить изменять данные клиентов.                                       | Значительный     |
|                                                   | **Потеря данных**               | Ошибки в базе данных могут привести к полной потере клиентской информации.                                | Критический       |
| **Секретные данные**               | **Утечка данных**               | Компрометация ключей API и паролей может привести к взлому всей системы.                                       | Критический       |
|                                                   | **Потеря данных**               | Потеря ключей шифрования может сделать данные клиентов недоступными.                                         | Критический       |
|                                                   | **Искажение данных**         | Взломанные учетные записи могут изменить критические параметры системы.                                   | Значительный     |

### **Выводы и рекомендации**

1. **Приоритетные угрозы**:
   * Наиболее критические риски связаны с утечкой данных клиентов и секретных данных (доступов и ключей API).
   * Потеря конфиденциальных данных (например, данных клиентов) может вызвать юридические последствия и штрафы.
   * Искажение данных в CRM и API может повлиять на работу сервисов и пользовательский опыт.
2. **Рекомендации**:
   * Разработать политику управления доступом (RBAC) для API.
   * Внедрить механизм мониторинга обращений к конфиденциальным данным.
   * Усилить контроль над ключами API и доступами (использование Vault).
   * Регулярно проверять процессы резервного копирования и восстановления данных.
