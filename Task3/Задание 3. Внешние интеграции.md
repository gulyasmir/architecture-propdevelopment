# **Требования к внешним интеграциям**

#### **Безопасность**

* **Шифрование**: Все запросы к платформе «Умный дом» передаются через HTTPS (TLS 1.2/1.3).
* **Аудит и логирование**: Все API-запросы и ответные действия логируются в системе SIEM.
* **Ограничение доступа**: Запросы к платформе «Умный дом» разрешены только через API Gateway PropDevelopment.
* **Политика хранения данных**: Биометрические данные и номера автомобилей хранятся только на стороне партнёра, PropDevelopment не хранит чувствительную информацию.

#### **Аутентификация и авторизация**

* **OAuth 2.0 / OpenID Connect**:
  * Собственники проходят аутентификацию через сервис пользователей PropDevelopment.
  * API взаимодействие с платформой «Умный дом» использует OAuth 2.0 (Client Credentials Flow).
* **RBAC (Role-Based Access Control)**:
  * Доступ к домофону и шлагбауму назначается через систему разрешений PropDevelopment.
  * Только авторизованные пользователи могут управлять устройствами.

#### **Взаимодействие систем**

* **Мобильное приложение** → **API Gateway** → **Адаптер интеграции** → **Платформа "Умный дом"**
* **Сценарий работы:**
  1. Пользователь запрашивает открытие двери через мобильное приложение.
  2. Запрос проходит через API Gateway PropDevelopment.
  3. API Gateway проверяет аутентификацию и права доступа.
  4. Данные передаются в платформу «Умный дом» через адаптер интеграции.
  5. Платформа управляет домофоном или шлагбаумом и отправляет ответ.

### **Итоговая схема взаимодействия**

1. **Собственник** → **Мобильное приложение**
2. **Мобильное приложение** → **API Gateway PropDevelopment**
3. **API Gateway** → **Платформа «Умный дом»**
4. **Платформа «Умный дом»** → **Сервис домофона** (если биометрия подтверждена)
5. **Платформа «Умный дом»** → **Сервис шлагбаума** (если номер авто подтверждён)
6. **API Gateway & Платформа «Умный дом»** → **Инфраструктура безопасности** (логирование, мониторинг)
