# Задание 4. Защита доступа к кластеру Kubernetes


| **Роль**       | **Описание**                                                                            | **Полномочия**                                                                                      | **Группа пользователей**          |
| ------------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **view-only**      | Просмотр ресурсов без изменений                                     | `get`, `list`, `watch` для всех namespace                                                              | Аналитики, аудиторы                 |
| **cluster-admin**  | Полный доступ к кластеру                                                   | Все действия (`*`), включая создание, удаление и управление RBAC | DevOps, системные админы              |
| **developer**      | Управление ресурсами, но без доступа к секретам и RBAC | `get`, `list`, `create`, `update`, `delete` для `deployments`, `pods`, `services`, `configmaps`            | Разработчики                             |
| **security-admin** | Управление безопасностью кластера                                | `get`, `list`, `watch`, `update` для `networkpolicies`, `secrets`, `roles`, `rolebindings`                 | Специалисты по безопасности |

**Скрипт создания пользователей в Kubernetes** - create_users.sh. Этот скрипт создаст двух пользователей **developer1** и **security1**, создаст для них сертификаты и добавит в кластер.

**Скрипт создания роле**й - create_roles.yaml.  Этот YAML-файл определяет роли **developer** и **security-admin**.

**Скрипт связывания пользователей с ролями** bind_roles.yaml. Этот YAML-файл связывает пользователей с их ролями.

**Запуск скриптов**

```

# Запуск Minikube
minikube start

# Создание пользователей
chmod +x create_users.sh
./create_users.sh

# Создание ролей
kubectl apply -f create_roles.yaml

# Назначение ролей пользователям
kubectl apply -f bind_roles.yaml

```

В результате **developer1** имеет доступ к управлению ресурсами (Pods, Services, Deployments), а **security1** управляет безопасностью (Secrets, RBAC, NetworkPolicies).
